## 2. 关键场景设计

这些是未来测试输入/断言设计，不是已执行脚本。

### S01：失败编辑不能破坏 redo

```text
init
create rect r1 10 20 30 40
move r1 5 0
undo
create circle r1 0 0 1
redo
show r1
```

断言：重复 id 创建失败；redo 仍能执行，r1 的 x 为 15，类型和其他属性不变。关联 A07、A19、A21。

### S02：新编辑解禁，但不能跨越 IO 屏障

```text
init
create rect r1 1 2 3 4
save explicit.svg
undo
redo
move r1 10 0
undo
undo
```

断言：save 成功后的 undo/redo 均为规定屏障错误；move 后 undo 恢复 x=1；按暂定 D05，再 undo 是空栈，不能删除保存前的 r1。关联 A04、A18、A20。

### S03：嵌套容器删除与精确恢复

创建 root 下 outer、outer 下 inner 与 a、inner 下 b；删除 inner 后 b 也不存在；undo 恢复 inner/b 的父级和位置。随后 move outer，使 a、b 一起移动；undo/redo 后通过 id 查询仍正确。关联 A08、A09、A18。

### S04：自动 id 不能撞上后出现的 id

导入前序为 `<rect/>`、`<g><rect id="rect1"/></g>`、`<rect/>`。先扫描全部 id，再给两个缺 id rect 分配 rect2/rect3，g 也补 id 并按前序发布警告。另一个含重复显式 id 的文件整体失败。关联 A02、A03。

### S05：组内顺序与失败原子性

根为 a,b,c,d，执行 `group pair c a`，按暂定 D03 得到 pair(a,c),b,d；undo 恢复 a,b,c,d。执行包含不存在 id 的 group、包含祖先与子孙的 group 后，树、索引和历史均不变。关联 A12、A18。

### S06：文本及 in 解析

创建文本 `"in"`、`"a in b"`、`""`、带引号/反斜杠的内容；分别有无 `in g1` 尾缀。颜色 #3366ff 和 Windows 引号路径不应被截断。保存 `<>&` 等文本再读回，内容语义不变。关联 A06、A22、A23。

### S07：样式缺省与继承

g 设置 fill red；一个子 rect 无 fill，一个子 rect 明确 fill blue。set g fill green 后分别继承 green 和保持 blue；undo 恢复；save/read 仍保留“子属性缺省/显式设置”的区别。关联 A04、A11、A23。

### S08：文件写失败与导入失败

使用 storage 测试替身模拟写入/替换失败，检查原目标内容、原文档、读入路径和历史未变化；读入在补 id 后发现无效值，检查没有泄漏警告及候选状态。系统集成阶段补真实文件场景，不依赖操作系统权限差异构造唯一测试。关联 A02—A04、A20。
