## 3. 必测范围

- 每个命令的正常场景；六种图形的参数和合法属性；创建到根及容器；显示与帮助；本阶段明确拒绝 box。
- 无文档、重复/不存在 id、非容器、祖先与子孙冲突、根级 ungroup、非法数字/因子、未知属性、错误引号及文件失败。
- group/delete/addto/ungroup 的整条历史单元；恢复父级、同级位置、id 索引、属性缺省和子类型；恢复副本与历史快照不能共享可写节点。
- undo 后失败命令保留 redo，新成功编辑清空 redo；文档命令屏障、查询不改变历史；无变化编辑按 D05 验证。
- 外部 SVG 自动 id 避开后出现的显式 id；读入失败不泄漏警告或计数；文本特殊字符、空文本、中文、Windows 路径、颜色 # 与 in 尾缀。
- 写入/替换失败后原目标、会话及历史保持；测试替身覆盖失败分支，另以临时目录验证真实文件操作。测试不修改用户原始 SVG，不依赖单一平台权限设置。
- 按 D09 最终决定验证 transform/viewBox/额外属性等支持范围；不支持内容必须明确失败，不静默丢弃。开放决策不能直接标为测试通过。

完整需求覆盖沿用 [acceptance.md](acceptance.md) 的 A01—A30 与 S01—S08，不另建互相矛盾的编号体系。

## 4. 阶段 8 的准入、执行与退出

### 准入条件

1. 阶段 3—7 的功能及相应持续测试已完成；CLI 可运行，测试入口真实存在。
2. D09 等影响验收的未定语义已形成实施基线，文档说明支持范围和确认状态。
3. 题目完整会话、流程图 A 及关键失败序列已有可重复的 fixtures；新增用例能够清楚说明期望结果。

### 执行顺序

1. 对照 A01—A29 核对测试证据，补齐遗漏的正常、边界及失败场景。
2. 执行类型/构建/风格与架构检查，以及单元、集成、端到端测试；记录环境、实际命令、结果和日志位置。
3. 对失败项记录复现、影响、原因及修复；增加相关回归用例并重新验证受影响部分。
4. 最终一次代码或配置修复后执行完整回归；已经通过且未受新变化影响的检查不无理由反复重跑。
5. 用浏览器预览真实输出文件；核对依赖和模式落点、实际目录、支持范围与课程主文档；记录结果。

### 退出条件

- A01—A29 在已确定需求/支持范围内都有可定位证据；适用的自动和人工检查通过，不留未执行的必做项。
- 没有阻碍课程必需功能或架构规范的未解决缺陷。确认不属于支持范围的限制说明理由，不能把题目必需功能降为限制来绕过验收。
- 每个已修复缺陷都有对应回归依据；最终完整回归针对最新代码，报告可辨认实际版本。
- 已编写真实的 doc/test-report.md，并将结果链接回验收清单和主文档的质量保证栏目。

A30 的提交推送由用户另行明确授权自动执行；用户明确暂不创建标签，截止时间未提供；阶段 8 通过本身不产生授权。
